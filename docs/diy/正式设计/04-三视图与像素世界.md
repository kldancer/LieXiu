# LieXiu 三视图与像素世界设计

## 1. 设计目标

LieXiu 的视觉产品不是三个彼此割裂的页面，而是一个 Mission Command Center 的三种观察模式：

- **Command：** 任务 DAG、角色、预算、Gate、交付与干预动作；
- **World：** 用空间、角色和动画表达同一编排状态；
- **Replay：** 按 Activity sequence 复盘状态迁移和协作过程。

角色执行详情是所有模式共享的 Inspector。切换模式、刷新、断线或回放时，选中的 Mission/TaskNode/Run/Artifact 应保持
可解释的一致关系。

## 2. 页面信息架构

```text
┌──────────────── Mission 状态 / Budget / Human Gate / 全局动作 ────────────────┐
│ 左侧：DAG / Team      中央：Command | World | Replay       右侧：Inspector │
│ 任务、依赖、角色      看板、Phaser 世界或时间回放           Run/Artifact/Review │
├──────────────── Activity timeline / warnings / collaboration ──────────────┤
└─────────────────────────────────────────────────────────────────────────────┘
```

URL 保存 `mode`、Mission 和核心 selection/sequence，确保刷新、深链和浏览器前进后退可恢复。Zustand 或组件状态只保存
面板宽度、相机、hover、临时筛选等 UI 状态，不保存业务真相。

当前大型 Mission 页面应拆为 `mission-shell`、`board`、`run-detail` 和 `world` 边界。共享选择协议只接受领域 ID，
禁止组件相互读取内部状态。

## 3. 单一 Projection

服务端 `MissionProjection` 是所有视图的唯一输入，包含：

- Mission 状态、revision、预算、deadline、Human Gate；
- TaskNode DAG、Duty/RoleProfile、Agent binding、Assignment/Run 当前态；
- Artifact、Review、lineage 和 delivery；
- Activity sequence、结构化协作摘要和 warning；
- 按需加载的 Run prompt、transcript、tool call、usage 和 failure detail。

前端 `view-model` 只做纯映射：Task/Run 状态到 Board column、World zone、Actor animation、徽标和颜色。WebSocket
到达后按游标拉增量；发现 sequence gap、超前游标或版本不兼容时重拉 Snapshot。

结构化 Mailbox 仍只通过 Activity 投影：三视图筛选 `subject_type=mailbox_message`，只接受冻结的 sent/consumed/expired/cancelled
摘要字段，不读取消息正文。相同 sequence 只建立一个 UI 行；畸形摘要和未知事件忽略而不改变业务状态。

## 4. Command 与 Inspector

Command 模式应优先回答：当前目标是什么、哪些节点可以运行、谁在负责、哪里阻塞、预算如何、Owner 需要做什么。

- 左侧支持 DAG/列表切换、依赖和角色筛选；
- 中央看板按规划、可执行、运行、审查、集成、完成/阻塞展示；
- 顶部集中展示 pause/cancel、计划批准、风险动作和最终交付 Gate；
- 右侧 Inspector 展示 Assignment/Run lineage、prompt、工具、transcript、Artifact、Review、usage、重试原因；
- 所有可变更动作调用显式 Command，包含权限、revision 和二次确认语义。

Inspector 的事实必须可定位到 Run/Artifact/Activity，不能用拼接 UI 文案替代后端失败原因。

Command 的协作区、World 的角色气泡/协作区和 Inspector 的 Run/Task 协作区使用同一 sequence、message ID 与 Run selection。
展示字段固定为类型、recipient、状态、expires 和 hops；hop=8 与 expired/cancelled 必须有非颜色的文本提示。Task transcript 与
Mailbox 摘要保持两个独立区块，防止把 provider 对话误当跨 Agent 领域消息。

## 5. 像素世界技术边界

目标是具备类星露谷的空间感和轻交互，而不是一张方块状态表，因此正式世界内核采用 Phaser，并通过 client-only dynamic
import 挂载到 React。React 负责产品壳、数据订阅、selection 和 Command；Phaser 负责地图、相机、角色、路径、动画、
气泡和命中检测。

建议模块边界：

```text
packages/views/orchestration/world/
├── world-model.ts          # Projection -> WorldModel 纯映射
├── visual-events.ts        # Activity -> 有界视觉事件
├── phaser-scene.ts         # scene 生命周期和增量同步
├── avatar-controller.ts    # 角色状态、移动和动画
├── map-loader.ts           # Tiled map、zone 和碰撞层
└── agent-world.tsx         # React/Phaser bridge
```

不把整个 Projection 交给 Phaser 自由解释。React 将稳定 `WorldModel` 与 sequence 化 `VisualEvent` 送入 scene；scene
卸载时必须清除 ticker、listener、texture 和 canvas，避免页面切换泄漏。

## 6. 世界语义

第一张地图固定为可理解的项目基地：

| Zone | 领域语义 | 典型表现 |
| --- | --- | --- |
| `planning_observatory` | Mission planning / Human Gate | Planner 观察星图、方案卷轴 |
| `execution_workshop` | ready/running executor | 工位、工具动画、并行角色 |
| `review_archive` | Artifact review | 书架、批注、批准/返工标识 |
| `integration_forge` | integration/delivery build | 合成台、交付光效 |
| `blocked_corner` | blocked/offline/budget exceeded | 警示、等待和求助气泡 |
| `delivery_plaza` | Mission completed | 最终 Artifact 与团队集合 |

Actor 的位置、寻路、朝向、相机和动画帧是可重建的视觉临时态，不写数据库。持久事实只有 Mission/Task/Run/Artifact/
Activity。刷新时根据当前 WorldModel 重新摆放；Replay 时根据历史 Activity 确定性重建。

## 7. 游戏化交互

- 点击角色：在共享 Inspector 选中其当前 Run；
- 点击房间/区域：过滤对应 Duty 或状态；
- 点击气泡/警告：跳转关联 Activity、blocker 或 Human Gate；
- 点击 Artifact：打开 lineage 与 Review；
- 世界中的 pause、retry、approve、reassign 仍调用同一后端 Command，不允许直接改变精灵状态；
- 角色对话仅展示结构化 Mailbox 摘要，不恢复无边界自由聊天；
- 成就、天气、装饰和奖励只能由可审计领域事实派生，不能反向影响调度优先级。

## 8. Replay 和一致性

Replay 以 Snapshot + Activity sequence 为输入，支持播放、暂停、倍速、拖动、按角色/Task/Run 筛选。每个 Activity
必须有稳定视觉映射或明确的“无视觉变化”处理；未知事件不得让播放器崩溃。

一致性不变量：

1. 同一 sequence 在 Command、World、Inspector 中指向同一领域对象；
2. 漏事件后重拉的最终 WorldModel 与连续消费结果一致；
3. Replay 不调用业务 Command，不写数据库；
4. 同一事件重放两次不重复生成永久视觉对象；
5. Actor 不因动画未完成而阻止新 Projection 生效。

断线、重连、Activity gap、reset 和游标不一致统一失效并重拉 MissionProjection；前端不保存 Mailbox 副本。后台到期扫描产生的
`mailbox.message_expired` 与发送/消费/取消使用同一 Activity sequence，因此恢复后的三个视图最终指向同一 message/Run。

## 9. 性能、可用性与美术

- Phaser 仅在 World 模式加载；大日志、transcript 和 Artifact 内容按需请求；
- scene 更新以实体 diff 和事件队列为单位，避免每帧重建全量对象；
- 定义 Actor/Activity 上限、离屏裁剪和低性能降级；
- 提供 reduced motion、暂停动画、键盘选择、文本状态、颜色之外的形状/徽标表达；
- 世界不可用时 Command 与 Inspector 仍能完成全部管理动作；
- 地图、sprite、音效使用原创或许可证清晰的资源，资产元数据记录来源和版本。

## 10. 参考项目的吸收边界

- Star Office UI：参考 Phaser 生命周期、区域、动画和资产组织，不复制 Flask/polling/巨型脚本；
- ClawLibrary：参考空间语义、房间资产与 debug overlay，不复制单体 Scene；
- Agent Monitor：参考 React/Canvas/Worker 的性能和增量同步思路；
- OpenOffice：参考团队、角色、worktree、review 的交互表达，不引入第二个 TypeScript Orchestrator；
- Control Center：参考只读安全、action queue、审批和 wiring UX；
- OpenClaw Admin：只参考 Runtime 管理，不恢复 Chat、Channel、Cron；
- 3D Monitor：仅作视觉灵感，不进入当前技术路线。

## 11. 验收门槛

- Command、World、Replay 和 Inspector 消费同一 Projection，刷新/断线/重启后收敛；
- A/B 并行、Review 返工、C 集成、blocked、offline、cancel 和 completed 均有明确视觉语义；
- World 与 React 往返切换无 listener/canvas 泄漏，低性能模式仍可管理 Mission；
- Actor/Zone 点击和 URL 深链稳定选中同一 Run；
- Replay 可从任意合法 sequence 恢复，未知事件 fail soft；
- 像素世界不写业务状态、不保存角色坐标、不成为第二事实源。
