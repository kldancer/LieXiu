# 多会话协同与持续推进机制

## 1. 文档定位

本文定义 Wave 1B、Wave 1C、Wave 2、Wave 3 的多会话研发协同方式。它只负责协同控制面，不重复定义产品领域合同、Wave 工作包或完成状态：

- 产品与架构事实以 02、07 为准；
- 功能删除边界以 03 为准；
- Wave 顺序和完成状态以 08 为唯一来源；
- 动态会话 ID、即时进度、命令输出和临时问题只写入 `.work/tasks/wave-program-coordination/`。

本机制参考 `jusuan-installer/docs/平台开发联调部署规范.md` 的会话协同思想，并按 LieXiu 单仓深度 DIY 的实际边界收敛。

## 2. 总体原则

主会话始终是唯一的全局交付 owner，负责：

1. 冻结当前 Wave 的业务合同、依赖 DAG、完成条件和回退边界；
2. 维护共享写集合，避免多个会话同时修改同一条编排主链；
3. 把真正独立的事实域或实现域派发给独立 Codex 会话；
4. 接收会话结论，判断是否采纳并统一集成，而不是机械拼接结果；
5. 运行跨域测试、数据库迁移、浏览器验收和文档收敛；
6. 只有实现、适用验证和运行事实齐全时才更新 08 的完成状态。

独立会话默认使用用户指定的 GPT-5.6 Luna。读取、清单和局部机械整改使用 `medium` 或更低思考强度；共享状态机、数据库事务、跨域迁移和最终集成由主会话保留。

## 3. 可并发任务判定

只有同时满足以下条件的任务才允许并发：

- 输入事实可在派发时固定；
- 产出可以独立验证；
- 写集合互不重叠，或者任务明确为只读；
- 不共同拥有同一个业务状态机、数据库迁移序列或公共 API 合同；
- 失败不会迫使另一个任务回滚已完成的共享修改。

优先并发的任务包括：

- 不同产品域的删除闭包审计；
- 前端视图、后端 Projection、像素资源等边界稳定后的独立实现；
- 无写入的调用链、依赖、测试缺口和运行事实审计；
- 已冻结接口下的局部测试补齐。

以下任务不并发写入：

- Orchestrator Command、状态机、Run/AgentTask 桥接；
- 同一 migration 序列、同一 sqlc query 文件或生成代码；
- Handler/Service 共享构造与路由装配；
- Wave 进度文档和跨域验证收据；
- 同一浏览器入口或同一本地数据库 fixture。

## 4. 会话角色与交付合同

### 4.1 主会话

主会话必须为每个独立任务给出：

- 精确目标和非目标；
- 只读或可写授权；
- 允许写入的绝对路径集合；
- 必读合同和当前基线；
- 最小验证接口；
- 首次反馈时间与硬止损时间；
- 输出格式和回传给主会话的证据。

主会话不会把“继续推进整个 Wave”直接派发给独立会话，也不会让多个会话分别设计同一个共享合同。

### 4.2 审计会话

审计会话默认只读，输出：

1. 真实业务链与实现链；
2. 缺口、风险和依赖顺序；
3. 建议的独立写集合；
4. 目标测试和验收入口；
5. 明确排除项。

审计结论只是输入，是否进入正式实现由主会话判断。

### 4.3 实现会话

实现会话只拥有一个边界稳定、可独立验收的工作包。未经主会话再次授权不得扩大路径、顺手重构、修改迁移序列、执行真实 Agent CLI、stage、commit、push 或远端写入。

实现完成时必须回传：

- 变更路径；
- 行为合同；
- 执行过的验证及结果；
- 未验证项、已知基线失败和剩余风险；
- 与其他车道的集成前提。

## 5. 分波协同策略

### Wave 1B

主会话保留 Orchestrator、Issue/Task 共享主链和 producer 白名单的唯一写权限。独立会话先审计不同 producer，只有在替代 Command 和调用边界冻结后，才把 Quick Create、Autopilot/Channel 等无重叠叶子实现分派出去。

### Wave 1C

C1 删除单元可以按页面→API→service→DB→配置→依赖→文档闭包并发审计；实际删除按依赖和共享文件分批执行。身份、Chat、Squad、Autopilot 等 C2 深耦合域串行进入主集成链。

### Wave 2

MissionProjection 和 Activity/重拉合同先由主会话冻结。之后总看板、执行详情、像素世界可以按独立前端目录并行实现，但必须消费同一个 Projection，禁止各自建立业务状态解释。

### Wave 3

无引用代码、配置依赖、品牌资源可以按写集合并发；schema 压缩、生成代码和黄金场景回归保持单一 owner。品牌替换只在旧产品域停止读写后进行，避免一边删除一边维护两套名称。

## 6. 集成与完成门禁

每个独立会话的产出进入主线前，主会话依次确认：

1. 任务没有越过授权写集合；
2. 业务语义与 07 的事实所有权一致；
3. 不新增 AgentTask、Run 或业务状态旁路；
4. 目标测试通过，默认测试不执行真实 Agent CLI；
5. 需要数据库或浏览器事实时，由主会话在共享工作区统一验证；
6. 动态证据进入 `.work`，稳定结论才进入 docs；
7. 08 的工作项只有在退出条件全部满足后才标记完成。

跨会话不采用重复的“实现会话自审→另一个会话再审→主会话再审”长链。局部实现自测后直接交给主会话做一次边界与集成复核；高风险状态机、迁移或安全变化再增加有针对性的独立只读审查。

## 7. 当前执行节奏

默认保持三类工作并行：

1. 主会话推进当前关键路径的共享实现；
2. 一个或多个 Luna 会话审计下一批可独立工作包；
3. 已冻结接口下的 Luna 实现会话执行互不重叠的叶子工作。

当独立会话尚未返回时，主会话继续完成不会被其结论推翻的共享工作；当某会话完成时，主会话在下一集成点吸收结论并更新后续 DAG。这样既保持持续推进，也避免用并发制造返工。
